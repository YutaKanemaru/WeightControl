## 各フェーズのゴール

1. **体重の記録と履歴**：体重（kg）と日時を入力して保存し、新しい順の一覧で見られる。前回からの増減も表示。スワイプで削除できる。
2. **プロフィールと目標**：カロリー計算や予測に必要な情報を一度だけ入力すればよい形にする。目標体重の入力欄では、ペースと BMI の目安をその場で見せる（BMI の考え方は [BMI_GOAL.md](BMI_GOAL.md)）。期限は目標体重とモード（ゆるやか／ハード）からアプリが提案し、自分で決めることもできる（[GOAL_DEADLINE.md](GOAL_DEADLINE.md)）。
3. **グラフと予測**：直近 3 週間の測った体重に直線（線形回帰）を引き、その傾きから「この調子だと何日に目標に届くか」を予測する。グラフには測った体重の点と、この直線（その先は点線の予測）、目標体重の横線と期限の縦線を描く。画面では「トレンド」という言葉や数字は出さない。
4. **カロリーと目標修正**：基礎代謝と運動量から 1 日の目安カロリーを出す。ペースが速すぎる目標には、現実的な期限を提案する。
5. **メッセージとヒント**：記録したこと自体をほめる。オーバー分を「おにぎり 1 個分」のように身近な食べ物で示す。
6. **カレンダー**：続けられている実感が持てるように、記録した日にスタンプを押す。
7. **HealthKit**：体重計アプリやヘルスケアと記録を共有し、歩数・消費カロリーを取り込む。
8. **通知**：記録を忘れないように、決まった時間にやさしくお知らせする。
9. **仕上げ**：免責表示、空の状態の画面、アクセシビリティ、アイコンなど。見た目は CLAUDE.md の「UI の見た目の方針」（ワークアウトアプリのような雰囲気）に合わせて整える。
10. **Apple Watch**：手首からすぐ記録できるようにする。
11. **課金のしくみ**：記録・グラフ・今のペース・カレンダー・通知はずっと無料のまま（分け方は [PRO.md](PRO.md)）、上位機能を買い切りの「Pro」（480〜800 円の想定）で解放する。StoreKit 2（Apple 純正の課金の仕組み）を使い、サーバーは使わない。設定画面に「購入を復元」ボタン（審査で必須）、任意で投げ銭。1 か月の無料お試しは 0 円の購入項目として始め（審査ガイドライン 3.1.1）、その購入日からお試しの期間を数える。Xcode の StoreKit Configuration ファイルで、本物のお金を使わずに購入を試せるようにする。
12. **Pro 機能**：「目標に届く日」（日付とグラフの点線の予測）、「チートデーの提案」（予定より先に進んでいるとき、維持カロリーまで食べる日をアプリが提案する）と、「この調子なら 3 月 8 日〜4 月 2 日ごろ」のような幅付きの予測。計算は `Logic/` にテスト付きで追加する。医療的な断定はしない。最初に 1 か月無料で試せて、終わったあとは項目を残したまま中身をぼかして「Pro で見られます」と出す（[PRO.md](PRO.md)）。
13. **英語版**：`Localizable.xcstrings` に英語を追加し、食品カロリー表の食品名・ほめるメッセージ・通知文も英語にする。体重の単位（kg / lb）の切り替えも検討する。App Store の説明文とスクリーンショットも英語で用意し、日本以外でも販売する。
14. **長く使い続けてもらうしくみ**：目標に届いた後の「維持モード」（画面での名前は「キープモード」。Pro 機能。体重の範囲を決めて、外れそうなときにやさしく知らせる。[MAINTENANCE_MODE.md](MAINTENANCE_MODE.md)）や、お正月明けなどの季節のプランを用意し、目標達成後も使う理由を作る。年額サブスクは開発と運用の負担が大きいため **保留**（2026-11-21 決定）。当面は買い切りの Pro だけにする。
15. **画面の作り直し**：CLAUDE.md の「UI の見た目の方針」（Apple のワークアウトアプリのような、シンプルでひと目で読める雰囲気）に沿って、ホーム・履歴・カレンダー・設定・入力画面を作り直す。大事な数字を大きく、情報はカードに分け、SF Symbols とシステムの色を使い、ダークモードと文字サイズの設定で崩れないようにする。Apple の画面の丸写しや、アクティビティリングなど Apple 独自のデザインのまねはしない。番号は 15 だが、App Store に出す前（課金のフェーズ 11 より前）に、フェーズ 9 の仕上げと一緒に進める。

## できているロジック（Logic/）

すべてテスト付きです。画面からは主に、ホームの `HomeDashboardBuilder`、目標の入力欄の `GoalPlanAdvisor`・`GoalBMIAdvisor` を通して使っています。

**予測・カロリー・目標**

| ファイル | 役割 |
|---|---|
| `LinearRegression` / `GoalForecaster` | 直近 21 日の測った体重に直線を当てはめ、今の体重の目安（直線の今日の値）とペース（傾き）から目標に届く日を予測（記録 3 日以上で予測、7 日未満は「精度は低め」の注意）。グラフにもこの直線を描く。`paceEstimate` はホームの安全チェック・カロリー計算にも使う |
| `ForecastLineBuilder` | グラフの直線と点線（目標までの予測）を描くための座標を作る |
| `WeightTrendCalculator` | EMA（指数移動平均：日々のブレをならす計算）でならした体重を出す。ほめるメッセージ（この 1 週間の流れ）だけに使い、画面に数字は出さない |
| `CalorieCalculator` | 基礎代謝（Mifflin-St Jeor 式）、1 日の消費カロリー、推奨摂取カロリー（下限：男性 1500・女性 1200 kcal と基礎代謝の大きいほう） |
| `EnergyExpenditureResolver` | 消費カロリーの計算方法を決める（自動：ヘルスケアに 7 日分以上の実績があればアクティブエネルギー、なければ活動係数。設定で手動選択も可） |
| `EnergyBalanceEstimator` | 体重の変化から、実際のカロリー収支を逆算 |
| `GoalSafetyChecker` | 減量は週 1%、増量は週 0.5% を超えるペースなら、現実的な期限・目標を提案 |
| `GoalPlanAdvisor` | 目標の入力中に「無理のないペースです」「少し速めです＋修正案」を出し分ける（判定は `GoalSafetyChecker`）。「自分で決める」のときだけ使う |
| `GoalDeadlineProposer` | 目標体重とペース（ゆるやか＝週に体重の 0.5 %・ハード＝1 %、増量はその半分）から期限を提案。減量は食事の下限で出せるペースで頭打ち、2 年より先なら手前の目標をすすめる。「約 3 か月」のような期間の言い方も（[GOAL_DEADLINE.md](GOAL_DEADLINE.md)） |
| `BodyMetrics` / `GoalBMIAdvisor` | BMI の計算と、目標体重の BMI の目安（18.5 未満は注意、25 以上は「最初の一歩」としてほめる・増やす目標なら注意）。詳しくは [BMI_GOAL.md](BMI_GOAL.md) |
| `HomeDashboardBuilder` | ホームに出すもの（グラフ・予測・カロリー・ほめる言葉・食べ物ヒント・目標の BMI）を、上のロジックを順に呼んで 1 つにまとめる |

## 収益化の方針

- まずは「基本無料＋買い切りの Pro」で最初の売上を目指す。Apple の App Store Small Business Program（参加無料、手数料が 30% → 15%）に申し込んでから課金を始める。
- 広告と、利用者のデータを研究機関などに売ることはしない。Apple の審査ガイドライン 5.1.3 で健康データの販売が禁止されていること、個人情報保護法の対応やサーバーが必要になること、「データは端末の中だけ」という強みが消えることが理由。
- App Store のプライバシー表示は「データの収集なし」を保つ。
