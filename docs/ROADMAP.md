## 各フェーズのゴール

1. **体重の記録と履歴**：体重（kg）と日時を入力して保存し、新しい順の一覧で見られる。前回からの増減も表示。スワイプで削除できる。
2. **プロフィールと目標**：カロリー計算や予測に必要な情報を一度だけ入力すればよい形にする。
3. **グラフと予測**：直近 3 週間の測った体重に直線（線形回帰）を引き、その傾きから「この調子だと何日に目標に届くか」を予測する。グラフには測った体重の点と、この直線（その先は点線の予測）、目標体重の横線と期限の縦線を描く。画面では「トレンド」という言葉や数字は出さない。
4. **カロリーと目標修正**：基礎代謝と運動量から 1 日の目安カロリーを出す。ペースが速すぎる目標には、現実的な期限を提案する。
5. **メッセージとヒント**：記録したこと自体をほめる。オーバー分を「おにぎり 1 個分」のように身近な食べ物で示す。
6. **カレンダー**：続けられている実感が持てるように、記録した日にスタンプを押す。
7. **HealthKit**：体重計アプリやヘルスケアと記録を共有し、歩数・消費カロリーを取り込む。
8. **通知**：記録を忘れないように、決まった時間にやさしくお知らせする。
9. **仕上げ**：免責表示、空の状態の画面、アクセシビリティ、アイコンなど。見た目は CLAUDE.md の「UI の見た目の方針」（ワークアウトアプリのような雰囲気）に合わせて整える。
10. **Apple Watch**：手首からすぐ記録できるようにする。
11. **課金のしくみ**：記録・グラフ・基本の予測・カレンダー・通知はずっと無料のまま、上位機能を買い切りの「Pro」（480〜800 円の想定）で解放する。StoreKit 2（Apple 純正の課金の仕組み）を使い、サーバーは使わない。設定画面に「購入を復元」ボタン（審査で必須）、任意で投げ銭。Xcode の StoreKit Configuration ファイルで、本物のお金を使わずに購入を試せるようにする。
12. **Pro 機能**：「チートデー計画」（平日に少しずつカロリーを貯めて、飲み会などの日に使える週単位の予算）と、「この調子なら 3 月 8 日〜4 月 2 日ごろ」のような幅付きの予測。計算は `Logic/` にテスト付きで追加する。医療的な断定はしない。
13. **英語版**：`Localizable.xcstrings` に英語を追加し、食品カロリー表の食品名・ほめるメッセージ・通知文も英語にする。体重の単位（kg / lb）の切り替えも検討する。App Store の説明文とスクリーンショットも英語で用意し、日本以外でも販売する。
14. **長く使い続けてもらうしくみ**：目標に届いた後の「維持モード」（体重の範囲を決めて、外れそうなときにやさしく知らせる）や、お正月明けなどの季節のプランを用意し、目標達成後も使う理由を作る。新機能を定期的に出せるようになったら、買い切りと並べて年額サブスクも検討する。
15. **画面の作り直し**：CLAUDE.md の「UI の見た目の方針」（Apple のワークアウトアプリのような、シンプルでひと目で読める雰囲気）に沿って、ホーム・履歴・カレンダー・設定・入力画面を作り直す。大事な数字を大きく、情報はカードに分け、SF Symbols とシステムの色を使い、ダークモードと文字サイズの設定で崩れないようにする。Apple の画面の丸写しや、アクティビティリングなど Apple 独自のデザインのまねはしない。番号は 15 だが、App Store に出す前（課金のフェーズ 11 より前）に、フェーズ 9 の仕上げと一緒に進める。

## できているロジック（Logic/）

すべてテスト付きです。フェーズ 3〜5 の分は、ホームタブ（#9）から `HomeDashboardBuilder` を通して使っています。

| ファイル | 役割 |
|---|---|
| `WeightTrendCalculator` | EMA（指数移動平均：日々のブレをならす計算）でならした体重を出す。記録が空いた日も考慮。ほめるメッセージ（この 1 週間の流れ）だけに使う |
| `LinearRegression` / `GoalForecaster` | 直近 21 日の測った体重に直線を当てはめ、今の体重の目安（直線の今日の値）とペース（傾き）から目標に届く日を予測（記録 3 日以上で予測、7 日未満は「精度は低め」の注意）。グラフにもこの直線を描く。`paceEstimate` はホームの安全チェック・カロリー計算にも使う |
| `ForecastLineBuilder` | グラフの点線（目標までの予測）を描くための座標を作る |
| `CalorieCalculator` | 基礎代謝（Mifflin-St Jeor 式）、1 日の消費カロリー、推奨摂取カロリー（下限つき） |
| `GoalSafetyChecker` | 減量は週 1%、増量は週 0.5% を超えるペースなら、現実的な期限・目標を提案 |
| `EnergyBalanceEstimator` | 体重の変化から、実際のカロリー収支を逆算 |
| `EnergyExpenditureResolver` | 消費カロリーの計算方法を決める（自動：ヘルスケアに 7 日分以上の実績があればアクティブエネルギー、なければ活動係数。設定で手動選択も可） |
| `Food/CalorieHintGenerator` | オーバーしたカロリーを「おにぎり 1 個分」のような身近な食べ物に言いかえる |
| `Messages/PraiseMessageGenerator` | トレンド・連続記録日数・目標への進み具合から、ほめるメッセージを作る |

| `Demo/DemoScenario` | 動作確認用のデモデータ（4 シナリオの固定の体重・プロフィール・目標） |
| `Calendar/CalendarMonthBuilder` | 月のカレンダーのマス目（曜日に合わせた空きマス、今日・未来の日の印）を作る |
| `Calendar/StampBook` | 体重・運動のスタンプがある日、今月のスタンプ数、連続日数。`ExerciseStampRule` は日付をタップしたときに押す・取り消すを決める |
| `Health/HealthWeightImportPlanner` | ヘルスケアの体重を取り込むときの重複防止（自分の書いた記録・同じ ID・10 分以内で 0.05 kg 以内）と、ヘルスケアで消された記録の扱い |
| `Health/DailyActivity` / `ExerciseStampSyncPlanner` | 1 日の運動量（エクササイズ・ワークアウト・歩数）から、運動スタンプを押す・書き換える・外す（手動のスタンプには触らない） |

## これまでに決めたこと

| 日付 | 決めたこと | 理由 |
|---|---|---|
| 2026-11-20 | 画面では「トレンド」という言葉と、その数字を出さない。グラフの線は「ならした流れ」、メッセージは「この1週間の流れで」と表示 | 測った体重と別の数字が並ぶと、どちらを見ればよいか迷うため |

| 2026-11-20 | 予測は直近 3 週間の測った体重への直線（線形回帰）から出す。EMA はグラフの見た目用に残す | EMA は実際の体重より遅れるため、予測が上振れしていた |
| 2026-11-20 | 予測の幅（楽観〜悲観の帯）は Pro 機能（フェーズ 12）にする | 無料版はシンプルな 1 本の予測にし、Pro の価値にするため |
| 2026-11-20 | グラフの「ならした流れ」（EMA）の線をやめ、直近 3 週間の直線と予測の点線だけにする。期限の縦線を追加。予測は記録 3 日から出し、7 日未満は「精度は低め」と注意する | 線が 3 種類あって分かりにくかったため。最初の 1 週間も見通しを出しつつ、ブレが大きいことを正直に伝えるため |
| 2026-11-20 | UI の見た目は Apple の「ワークアウト」アプリのような雰囲気（HIG 準拠・標準の部品・大きな数字・カード・SF Symbols・ダークモード対応）。Apple 独自のデザインのまねはしない（詳しくは CLAUDE.md の「UI の見た目の方針」） | シンプルでひと目で読めるようにするため |

## 収益化の方針

- まずは「基本無料＋買い切りの Pro」で最初の売上を目指す。Apple の App Store Small Business Program（参加無料、手数料が 30% → 15%）に申し込んでから課金を始める。
- 広告と、利用者のデータを研究機関などに売ることはしない。Apple の審査ガイドライン 5.1.3 で健康データの販売が禁止されていること、個人情報保護法の対応やサーバーが必要になること、「データは端末の中だけ」という強みが消えることが理由。
- App Store のプライバシー表示は「データの収集なし」を保つ。
