# デモデータで予測・カロリーを確かめる

ホームタブの「体重（最新の体重・目標まで）」「グラフ（測った体重の点・直近 3 週間の直線・予測の点線・目標と期限の線）」「達成の見込み」「無理な目標の修正案」「1 日の摂取カロリーの目安」「食べ物ヒント」「ほめるメッセージ」が、計算式どおりに出ているかを、自分の目で確かめるための資料です。

4 つのシナリオを用意しました。それぞれ **入力データ → 計算の途中 → 画面に出るはずの値** の順に書いています。
ここに書いた値は、テスト（`WeightControlAppTests/DemoScenarioTests.swift`）でアプリと同じロジックを使って計算し、一致することを確かめています。

> 予測やカロリーは一般的な計算式による目安で、医療アドバイスではありません。

---

## 1. 読み込みかた

1. Xcode でシミュレーター（例: iPhone 17）を選んで ▶︎ で実行します（Debug ビルド）。
2. **設定** タブの一番下に「開発用：デモデータ」が出ます。
3. シナリオのボタンを押し、「消して読み込む」を選びます。
4. **ホーム** タブを開いて、下の「画面に出るはずの値」と見比べます。シナリオを変えるときは 2〜3 をくり返します。

### 注意

- **今の記録・プロフィール・目標・運動スタンプはすべて消えます。** 本物の記録が入っている iPhone ではなく、シミュレーターで試してください。
- このセクションは `#if DEBUG`（Debug ビルドのときだけコードを入れるしくみ）で囲んでいるので、App Store 版には入りません。
- **ヘルスケア連携はオフ** にしておいてください。オンだと、ヘルスケアの体重が取り込まれたり、消費カロリーがヘルスケアの実績で計算されたりして値がずれます。
- 読み込むと、設定の「消費カロリー」の計算方法は「自動」に戻ります（連携オフなら活動量で計算されます）。
- 日付は「読み込んだ日」が最後の記録になるようにずらします。下の表の「例」の日付は **2026/11/20 に読み込んだ場合** です。別の日に読み込んだら、「今日から何日後」で読みかえてください。
- 読み込んだ **当日** に確認してください。次の日になると「今日」がずれて、期限までの日数などが変わります（そのときはもう一度読み込めば OK）。

## 2. 使っている計算式

予測とカロリーは、**直近 3 週間（21 日）の測った体重に引いた直線** をもとに計算します。

| 何を | 式 | 決まった数 |
|---|---|---|
| 予測の直線 | 直近 21 日の体重（同じ日に何回か測ったら平均）に、線形回帰（最小二乗法：各点との縦のずれの 2 乗の合計がいちばん小さくなる直線）で直線を引く | 記録 3 日以上で予測。7 日未満は「予測の精度は低め」の注意を出す |
| 今の体重の目安 | 直線の「今日（最後の記録の日）」の値 | 記録 3 日未満のときは、ならした流れの最新の値 |
| 今のペース（kg/週） | 直線の傾き（kg/日）× 7 | 週 0.01 kg 未満は「横ばい」 |
| 目標に届く日 | 最後の記録日 ＋ 切り上げ（（目標 − 今の体重の目安）÷ 傾き（kg/日）） | 730 日より先なら出さない |
| 期限に間に合わせるペース | （目標 − 今の体重の目安）÷（期限までの日数 ÷ 7） | |
| 無理のないペースの上限 | 減量：今の体重の目安 × 1 %／週 | 増量は 0.5 %／週 |
| 修正案の期限 | 今日 ＋ 切り上げ（残り kg ÷ 上限ペース × 7）日 | |
| 修正案の目標体重 | 今の体重の目安 ＋ 上限ペース ×（期限までの日数 ÷ 7）を 0.1 kg 単位に（今の体重に近い側へ）丸める | |
| 基礎代謝（Mifflin-St Jeor 式） | 男性 10×体重 ＋ 6.25×身長 − 5×年齢 ＋ 5、女性は最後が − 161 | 体重は **今の体重の目安** を使う |
| 消費カロリー（TDEE） | 基礎代謝 × 活動係数（ヘルスケアに 7 日分以上の実績があるときは（基礎代謝 ＋ 平均アクティブエネルギー）÷ 0.9） | ほぼ座りっぱなし 1.2、軽い運動 1.375。デモデータにはヘルスケアの実績がないので、いつも活動係数で計算します |
| 摂取カロリーの目安 | TDEE ＋ 計画ペース × 7200 ÷ 7。ただし下限 ＝ max（基礎代謝, 男性 1500／女性 1200） | 体脂肪 1 kg ≈ 7200 kcal |
| 計画ペース | 無理のない目標なら「期限に間に合わせるペース」、速すぎる目標なら「上限ペース」 | |
| 計画よりどれだけ多いか | 今のペース × 7200 ÷ 7 − 計画ペース × 7200 ÷ 7 | 記録 14 日以上・減量のときだけ。50 kcal 未満なら出さない |
| ならした流れ（EMA） | 今日の値 ＝ 昨日の値 ＋ 0.1 ×（今日の体重 − 昨日の値）。最初の日は体重そのもの（EMA：指数移動平均） | ほめるメッセージだけに使う（グラフには描かない） |
| ほめるメッセージ | 7 日前と比べた「ならした流れ」の変化が 0.2 kg 未満なら「安定」、目標の向きに動いていれば「この1週間の流れで〇kg下がっています」 | |

### なぜ「ならした流れ」ではなく直線で予測するのか

以前は、ならした流れ（EMA）に直線を引いて予測していました。でも EMA は毎日「差の 1 割」しか動かないので、減っている途中ではいつも実際の体重より **上に遅れて** 出ます。
たとえば ① では、ならした流れの最新の値は 70.66 kg ですが、最近の体重はもう 70 kg 前後です。この値から予測すると、到達日が実際より遅く（以前の計算では 52 日後）出ていました。

測った体重 21 点に直線を引けば、1 日だけの上下はほかの日と打ち消し合うので、**遅れがなく、1 日のブレにも振り回されにくい** 予測になります（① は 27 日後）。
グラフにも、この直線をそのまま描きます（直近 3 週間の部分は実線、その先の予測は点線）。以前はなめらかな「ならした流れ」の線も描いていましたが、測った体重・直線と 3 種類の線が並んで分かりにくかったため、やめました。日々の上下（ブレ）は点のまま見せます。

記録が少ないうちは、1 日のブレで直線の向きが大きく変わります。そこで記録 3 日から予測を出しつつ、7 日分たまるまでは「予測の精度は低め」の注意（オレンジ）をグラフと達成の見込みのカードに出します。

## 7. ほかにも試せること

- デモデータを読み込んだあと、ホームの「＋」で体重を足すと、ペース・予測がその場で変わります。たとえば ④ で 4 日分足して 14 日にすると、食べ物ヒントが出るかどうかの判定が始まります。記録が 3〜6 日のときの「精度は低め」の注意は、デモデータではなく自分で数日分を記録するか、Xcode のプレビュー「記録 4 日（精度が低め）」で確かめられます。
- 設定タブで活動量を変えると、TDEE と摂取目安が「基礎代謝 × 新しい係数」で変わります。
- 予測の幅（「3 月 8 日〜4 月 2 日ごろ」のような楽観〜悲観の帯）は、Pro 機能（フェーズ 12）で追加する予定です。
- 期待値は `WeightControlAppTests/DemoScenarioTests.swift` のテストと同じです。ロジックを変えてテストが失敗したら、この資料の値も一緒に直してください。
