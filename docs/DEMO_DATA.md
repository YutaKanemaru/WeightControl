# デモデータで予測・カロリーを確かめる

ホームタブの「グラフ（トレンド線・予測の点線）」「達成の見込み」「無理な目標の修正案」「1 日の摂取カロリーの目安」「食べ物ヒント」「ほめるメッセージ」が、計算式どおりに出ているかを、自分の目で確かめるための資料です。

4 つのシナリオを用意しました。それぞれ **入力データ → 計算の途中 → 画面に出るはずの値** の順に書いています。
ここに書いた値は、テスト（`WeightControlAppTests/DemoScenarioTests.swift`）でアプリと同じロジックを使って計算し、一致することを確かめています。

> 予測やカロリーは一般的な計算式による目安で、医療アドバイスではありません。

---

## 1. 読み込みかた

1. Xcode でシミュレーター（例: iPhone 17）を選んで ▶︎ で実行します（Debug ビルド）。
2. **設定** タブの一番下に「開発用：デモデータ」が出ます。
3. シナリオのボタンを押し、「消して読み込む」を選びます。
4. **ホーム** タブを開いて、下の「画面に出るはずの値」と見比べます。シナリオを変えるときは 2〜3 をくり返します。

### 注意

- **今の記録・プロフィール・目標・運動スタンプはすべて消えます。** 本物の記録が入っている iPhone ではなく、シミュレーターで試してください。
- このセクションは `#if DEBUG`（Debug ビルドのときだけコードを入れるしくみ）で囲んでいるので、App Store 版には入りません。
- **ヘルスケア連携はオフ** にしておいてください。オンだと、ヘルスケアの体重が取り込まれて値がずれます。
- 日付は「読み込んだ日」が最後の記録になるようにずらします。下の表の「例」の日付は **2026/11/20 に読み込んだ場合** です。別の日に読み込んだら、「今日から何日後」で読みかえてください。
- 読み込んだ **当日** に確認してください。次の日になると「今日」がずれて、期限までの日数などが変わります（そのときはもう一度読み込めば OK）。

---

## 2. 使っている計算式

| 何を | 式 | 決まった数 |
|---|---|---|
| トレンド（EMA：指数移動平均） | 今日のトレンド ＝ 昨日のトレンド ＋ 0.1 ×（今日の体重 − 昨日のトレンド）。最初の日は体重そのもの | ならし割合 0.1 |
| 今のペース（kg/週） | 直近 28 日の **トレンド** に線形回帰（最小二乗法）で直線を引き、その傾き（kg/日）× 7 | 7 日以上で予測、14 日未満は「参考値」 |
| 目標に届く日 | 最後の記録日 ＋ 切り上げ（（目標 − 今のトレンド）÷ 傾き（kg/日）） | 730 日より先なら出さない |
| 期限に間に合わせるペース | （目標 − 今のトレンド）÷（期限までの日数 ÷ 7） | |
| 無理のないペースの上限 | 減量：今のトレンド × 1 %／週 | 増量は 0.5 %／週 |
| 修正案の期限 | 今日 ＋ 切り上げ（残り kg ÷ 上限ペース × 7）日 | |
| 修正案の目標体重 | 今のトレンド ＋ 上限ペース ×（期限までの日数 ÷ 7）を 0.1 kg 単位に（今の体重に近い側へ）丸める | |
| 基礎代謝（Mifflin-St Jeor 式） | 男性 10×体重 ＋ 6.25×身長 − 5×年齢 ＋ 5、女性は最後が − 161 | 体重は **今のトレンド** を使う |
| 消費カロリー（TDEE） | 基礎代謝 × 活動係数 | ほぼ座りっぱなし 1.2、軽い運動 1.375 |
| 摂取カロリーの目安 | TDEE ＋ 計画ペース × 7200 ÷ 7。ただし下限 ＝ max（基礎代謝, 男性 1500／女性 1200） | 体脂肪 1 kg ≈ 7200 kcal |
| 計画ペース | 無理のない目標なら「期限に間に合わせるペース」、速すぎる目標なら「上限ペース」 | |
| 計画よりどれだけ多いか | 今のペース × 7200 ÷ 7 − 計画ペース × 7200 ÷ 7 | 記録 14 日以上・減量のときだけ。50 kcal 未満なら出さない |
| ほめるメッセージ | 7 日前と比べたトレンドの変化が 0.2 kg 未満なら「安定」、目標の向きに動いていれば「〇kg下がっています」 | |

### 見どころ：本当のペースより「ゆっくり」に出る

デモデータは「週 0.5 kg ずつ減る」ように作っていますが、画面の「今のペース」は **週 −0.4 kg**（−0.36）です。
これはバグではなく、EMA のしくみによるものです。トレンドは毎日「差の 1 割」しか動かないので、体重の変化に少し遅れてついていきます。さらに最初の日は「体重そのもの」から始まるため、はじめの数日はほとんど動きません。そのトレンドに直線を引くので、傾きは本当のペースより小さくなります。
記録が増えるほど（数か月分たまると）、このずれは小さくなります。

### 計算の途中

- 今のトレンド：**59.853 kg**
- 今のペース：**−0.127 kg/週**（記録 10 日なので「参考値」）
- 目標に届く日：（57.0 − 59.853）÷ −0.01808 ＝ 157.8 → **158 日後**。期限（90 日後）に間に合わない
- 期限に間に合わせるペース：−2.853 ÷（90 ÷ 7）＝ **−0.222 kg/週** → 上限 −0.599 kg/週より小さいので無理のない目標

## 7. ほかにも試せること

- デモデータを読み込んだあと、ホームの「＋」で体重を足すと、トレンド・ペース・予測がその場で変わります。たとえば ④ で 4 日分足して 14 日にすると「参考値」の注意書きが消え、食べ物ヒントが出るかどうかの判定が始まります。
- 設定タブで活動量を変えると、TDEE と摂取目安が「基礎代謝 × 新しい係数」で変わります。
- 期待値は `WeightControlAppTests/DemoScenarioTests.swift` のテストと同じです。ロジックを変えてテストが失敗したら、この資料の値も一緒に直してください。
